PERIOD

.NET developer

보안과 기밀 유지를 위해 내부 역할 정의, 승인 정책, 문서 서식, 데이터 구조 및 실제 진료 문서·환자 정보는 공개하지 않습니다.

Context & Constraints

2024년 비상진료 대응 환경에서 전담간호사가 작성한 임상 문서를 담당의가 검토·코사인할 수 있도록, 작성 역할과 최종 승인 역할을 HIS 업무 흐름 안에서 구분할 필요가 있었습니다. 또한 수술·수술후·퇴원기록을 포함한 기존 진료기록 화면에서 승인 진행 상태를 확인하고 처리할 수 있어야 했습니다.

보건복지부 비상진료 관련 공식 안내 ↗

System Flow

전담간호사 초안 작성
→
담당의 지정
→
코사인 대기 문서 조회·연결
→
담당의 검토·코사인
→
역할·문서 서식별 승인 검증
→
문서 상태·서명 정보 갱신

초안 작성부터 담당의 지정, 대기 문서 연결, 코사인, 승인 검증과 상태 갱신까지를 하나의 업무 흐름으로 구성했습니다.

Engineering Decisions

작성과 승인 책임 분리

전담간호사가 문서를 초안으로 작성하는 흐름과 담당의가 코사인으로 확인하는 흐름을 구분했습니다. 각 단계의 역할을 문서 상태에 반영해 작성과 승인 과정을 혼동하지 않도록 하기 위해서였습니다.

역할·문서 서식별 승인 검증

모든 문서에 동일한 조건을 적용하지 않고, 역할과 문서 서식에 따라 필요한 승인 조건을 확인하도록 구성했습니다. 기존 임상 문서 흐름을 유지하면서 필요한 경우에만 코사인 단계를 연결하기 위한 판단이었습니다.

코사인 대기 문서의 가시성

기존 코사인 의뢰 여부를 조회하고, 대기 문서를 의사 검토 흐름으로 연결하도록 구성했습니다. 담당의 선택과 승인 진행 상태가 현업 화면에서 확인되도록 하기 위해서였습니다.

기존 임상 기록과의 연계

수술·수술후·퇴원기록의 진단과 서명 정보를 승인 흐름과 연결했습니다. 별도의 승인 화면을 늘리기보다 기존 진료기록 업무 안에서 필요한 단계가 이어지도록 하기 위해서였습니다.

업무 규칙의 계층 연결

WPF 화면의 선택·제어 결과가 DTO를 거쳐 업무·데이터 계층의 승인 규칙과 상태 처리로 이어지도록 구성했습니다. 화면 조건과 저장 결과가 서로 다르게 동작하지 않도록 하기 위한 구조였습니다.

My Contribution

  • 전담간호사 작성 문서의 담당의 선택·코사인 UI 흐름 구현
  • 역할·문서 서식별 승인 조건과 문서·서명 상태 갱신 규칙 구현
  • 코사인 대기 문서 조회·연결과 수술·수술후·퇴원기록의 진단·서명 연계 고도화
  • WPF 화면부터 DTO, 업무서비스, 데이터 계층까지 승인 워크플로우 연계

Validation & Outcome

전담간호사 초안 작성, 담당의 지정, 코사인 대기 문서 연결, 담당의 검토·코사인, 역할·문서 서식별 승인 검증과 문서·서명 상태 갱신까지의 흐름을 구현했습니다. 비상진료 대응 환경에서 작성과 최종 승인 역할을 기존 HIS 진료기록 업무 안에서 구분하고 처리할 수 있도록 했습니다.
