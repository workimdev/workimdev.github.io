ezMemo PC 정식 출시

기존 사용자 데이터를 보호하면서 Local-First 구조를 발전시키는 Windows 메모 애플리케이션 개선

ORGANIZATION
인라이플 · 모비소프트 개발팀
PERIOD
2025.09 — 현재
ROLE
.NET developer
STACK
C# · .NET · WPF · MVVM · SQLite · MySQL · WebSocket

보안과 기밀 유지를 위해 내부 시스템 식별 정보, 운영 데이터, 미출시 구현 상세는 공개하지 않습니다.

Context & Constraints

ezMemo는 기존 사용자의 데이터와 사용 경험을 유지하면서 데스크톱 구조를 발전시켜야 했습니다. 네트워크 상태가 바뀌어도 메모 작성과 조회가 안정적으로 이어져야 했고, 업데이트를 통해 새로운 저장 구조를 도입하더라도 사용자가 초기화나 수동 이전을 하지 않도록 해야 했습니다.

System Flow

데스크톱 UI

사용자가 작업하는 기준은 로컬 저장소로 두고, 서버 반영은 비동기로 처리했습니다. 일시적인 네트워크 문제로 메모 작성과 조회 경험이 끊기지 않도록 하기 위해서였습니다.

Engineering Decisions

Local-First 데이터 흐름

사용자의 작성·수정 결과를 먼저 로컬 저장소에 반영하고, 서버 동기화는 별도로 처리하도록 구성했습니다. 네트워크 상태가 일시적으로 바뀌어도 메모 작성과 조회 경험이 끊기지 않도록 하기 위해서였습니다.

단계적 데이터 마이그레이션

기존 데이터와 새로운 저장 구조가 공존하는 전환 과정에서 버전별 마이그레이션 순서와 의존성을 관리했습니다. 중간 실패가 데이터 손실로 이어지지 않도록 트랜잭션과 재실행 가능성을 고려했습니다.

동기화 상태와 복구 경로

로컬 변경 여부와 서버 반영 상태를 구분하고, 연결이 회복되면 미전송 데이터를 다시 처리하도록 흐름을 정리했습니다. 데이터 유형 간의 참조 관계를 고려해 동기화 중 정합성이 깨지지 않도록 했습니다.

업데이트 후의 사용자 경험

저장 위치, 설정, 알람처럼 기존 사용 경험에 영향을 주는 요소가 업데이트 이후에도 자연스럽게 이어지도록 데이터 전환과 앱 업데이트 흐름을 함께 점검했습니다.

AI 협업 개발 하네스 및 CI/CD 자동화

ezMemo를 첫 적용 대상으로 하네스 엔지니어링 기반의 개발 자동화를 도입하고, AI 작업부터 CI/CD 배포까지 연결되는 개발 인프라를 설계·구축했습니다.

지식 환류
  • 동기화·마이그레이션 등 변경 위험이 큰 영역의 지식과 과거 사고를 프로젝트 스킬로 구조화
  • AI 병렬 작업을 feature 브랜치와 독립 worktree에서 수행하도록 구성
  • Jenkins와 GitHub Actions를 연결해 PR 빌드, 시크릿 검사, Claude 코드 리뷰와 상태 반환 자동화
  • Git Flow와 CI/CD 파이프라인을 기반으로 코드 반영부터 릴리스·배포까지 이어지는 자동화 인프라 구축
  • 계획 승인, 실제 애플리케이션 QA, 최종 머지·배포 판단은 사람이 유지하도록 권한 분리
  • 작업 결과와 사고를 플랜·커밋·incident·스킬에 환류해 다음 AI 작업에서 재사용

AI 작업이 코드 생성에서 끝나지 않고 검증·리뷰·배포·학습으로 이어지는 엔드투엔드 흐름을 구축하고, 실제 개발 과정에서 핵심 자동화 경로를 검증했습니다.

Validation & Outcome

로컬 저장, 데이터 전환, 서버 동기화, 업데이트 이후 재사용까지의 핵심 흐름을 검증했습니다. 네트워크 상태 변화와 구조 전환 과정에서도 기존 사용자 데이터를 보호하고, 메모 작성과 조회가 계속 가능한 기반을 마련했습니다. 동시에 프로젝트 맥락과 검증 기준을 축적해, 이후 변경에서도 같은 실수를 반복하지 않도록 하는 개발 운영 기반을 만들었습니다.
