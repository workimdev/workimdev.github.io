TECHNICAL CASE STUDY

ezMemo PC 정식 출시

모바일 버전과 데이터를 공유·동기화하도록 Local-First 구조로 전환하고 정식 출시한 Windows 메모 애플리케이션

ORGANIZATION
인라이플 · 모비소프트 개발팀
PERIOD
2025.09 — 현재
ROLE
.NET developer
STACK
C# · .NET · WPF · MVVM · SQLite · MySQL · WebSocket

보안과 기밀 유지를 위해 내부 시스템 식별 정보, 운영 데이터, 미출시 구현 상세는 공개하지 않습니다.

Context & Constraints

모바일 버전 출시를 위해 PC와 모바일이 동일한 데이터 모델과 동기화 규칙을 사용하도록 기존 PC 중심 저장 구조를 재설계해야 했습니다. 동시에 기존 사용자 데이터와 사용 경험을 유지해야 했고, 네트워크 상태가 바뀌어도 메모 작성과 조회가 안정적으로 이어져야 했습니다. 업데이트를 통해 새로운 구조를 도입하더라도 사용자가 초기화나 수동 이전을 하지 않도록 해야 했습니다.

System Flow

PC 데스크톱 UI
↔
로컬 SQLite 저장
↔
변경 상태 관리
↔
서버 동기화·재시도
↔
공통 데이터 모델
↔
모바일 앱

PC 앱은 로컬 저장소를 작업 기준으로 사용하고, PC와 모바일은 공통 데이터 모델과 동기화 규칙을 통해 데이터를 공유합니다. 오프라인 변경은 연결 복구 후 다시 동기화하도록 구성했습니다.

Engineering Decisions

PC·모바일 공통 데이터 흐름

PC와 모바일이 동일한 데이터 모델과 동기화 규칙을 사용하도록 구성했습니다. PC에서는 작성·수정 결과를 먼저 로컬 저장소에 반영하고 서버 동기화를 별도로 처리해, 네트워크 상태가 바뀌어도 작업을 이어갈 수 있도록 했습니다.

단계적 데이터 마이그레이션

기존 데이터와 새로운 저장 구조가 공존하는 전환 과정에서 버전별 마이그레이션 순서와 의존성을 관리했습니다. 중간 실패가 데이터 손실로 이어지지 않도록 트랜잭션과 재실행 가능성을 고려했습니다.

동기화 상태와 복구 경로

로컬 변경 여부와 서버 반영 상태를 구분하고, 연결이 회복되면 미전송 데이터를 다시 처리하도록 흐름을 정리했습니다. 데이터 유형 간의 참조 관계를 고려해 동기화 중 정합성이 깨지지 않도록 했습니다.

업데이트 후의 사용자 경험

저장 위치, 설정, 알람처럼 기존 사용 경험에 영향을 주는 요소가 업데이트 이후에도 자연스럽게 이어지도록 데이터 전환과 앱 업데이트 흐름을 함께 점검했습니다.

AI 협업 개발 하네스와 CI/CD 자동화

ezMemo에 AI 협업 개발 하네스를 처음 적용해, 프로젝트 지식·격리된 구현·자동 검증·사람 승인·배포가 이어지는 개발 흐름을 설계·구축했습니다.

지식 환류
  • 동기화·마이그레이션 등 고위험 변경 영역의 지식과 과거 이슈를 프로젝트 스킬과 검증 기준으로 구조화
  • plan-first 승인 흐름과 feature 브랜치·독립 worktree를 활용해 AI 병렬 작업을 격리
  • Jenkins·GitHub Actions로 PR 빌드, 시크릿 검사, AI 코드 리뷰와 상태 반환을 자동화
  • 코드 반영부터 릴리스·배포까지 연결하되 실제 앱 QA와 최종 판단은 사람이 수행하고, 결과와 incident를 프로젝트 지식으로 환류

AI 작업을 독립된 변경 단위로 수행하고 자동 검증과 사람의 최종 판단을 거쳐 배포되도록 구성했습니다.

Validation & Outcome

PC와 모바일이 동일한 데이터 모델과 동기화 규칙을 사용하도록 기존 PC 중심 구조를 Local-First로 전환하고, 기존 사용자 데이터 마이그레이션과 설치·자동 업데이트까지 구현·검증해 ezMemo PC를 정식 출시했습니다. 네트워크 상태가 변해도 메모 작성과 조회가 이어지고, PC와 모바일에서 데이터 연속성을 유지할 수 있도록 했습니다. 정식 출시 후 일평균 다운로드는 베타 운영 대비 약 80% 증가했고, 최고 일 다운로드는 베타 평균 대비 약 4배를 기록했으며 DAU도 유사한 증가 추세를 보였습니다.
