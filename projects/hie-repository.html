TECHNICAL CASE STUDY

진료정보교류 거점 문서저장소 이관 대응

통합 거점의 의뢰·회송 수신을 기존 HIS 업무 흐름에 재연결한 이관 대응 프로젝트

ORGANIZATION
이지케어텍 · 분당서울대학교병원
PERIOD
2024
ROLE
.NET developer
STACK
C# · .NET · WPF · REST API · Oracle · JSON

보안과 기밀 유지를 위해 기관·시스템 식별 정보, 연동 설정, 데이터 구조, 실제 진료 문서·첨부파일 및 환자 정보는 공개하지 않습니다.

Context & Constraints

진료정보교류 거점 문서저장소의 통합 이관에 맞춰, 외부 알림을 수신한 뒤 기존 HIS의 의뢰·회송 업무 흐름 안에서 처리할 수 있도록 연동을 정비했습니다. 외래와 응급 업무 화면에서 수신 문서를 계속 확인할 수 있어야 했고, 외부 환자 식별 정보와 내부 등록 정보의 연결, 문서 메타데이터와 첨부파일 처리, 기존 화면 흐름의 유지가 함께 필요했습니다.

System Flow

통합 거점 알림 API
→
알림 응답 매핑
→
환자 식별 연계
→
문서 메타데이터·첨부파일 처리
→
업무·데이터 계층
→
외래·응급 의뢰/회송 화면

알림을 수신하는 데서 끝내지 않고, 내부 업무에 필요한 형태로 연결·저장한 뒤 기존 목록을 갱신하도록 구성했습니다.

Engineering Decisions

환경별 연동 경계

연동 대상의 환경별 설정을 코드의 업무 로직과 분리해 관리했습니다. 통합 거점 전환에 따른 연결 지점의 변경이 화면과 저장 로직에 넓게 번지지 않도록 하기 위해서였습니다.

환자 식별 연계 단계 분리

외부에서 받은 환자 식별 정보를 내부 환자 등록 정보와 연결하는 단계를 수신 흐름 안에 분리했습니다. 수신 문서가 기존 진료 업무에서 올바른 대상과 함께 조회될 수 있도록 하기 위한 판단이었습니다.

문서와 첨부파일의 처리 흐름

의뢰·회송 문서의 메타데이터와 첨부파일 정보를 내부 업무·데이터 계층으로 전달하는 흐름을 정리했습니다. 외부 알림의 정보를 기존 업무 화면에서 활용할 수 있는 형태로 연결하기 위해서였습니다.

운영 흐름을 고려한 수신

외래·응급 업무에서 수동 및 주기적 조회 흐름을 제공하고, 조회 기간을 제한했습니다. 저장 뒤에는 기존 의뢰·회송 목록을 다시 조회해 현업이 익숙한 화면 흐름에서 수신 결과를 확인하도록 했습니다.

My Contribution

  • 통합 거점 알림 API client와 환경별 연동 설정 처리 구현
  • 외래·응급 수신 조회, 주기 조회, 조회 기간 검증 흐름 구현
  • 외부 환자 식별 정보와 내부 환자 등록 정보의 연계, 의뢰·회송 메타데이터 저장 흐름 구현
  • 문서 첨부파일 처리와 기존 의뢰·회송 목록 갱신을 업무·데이터 계층과 연계

Validation & Outcome

알림 수신, 환자 식별 연계, 문서 메타데이터·첨부파일 처리, 내부 저장과 기존 목록 갱신까지의 흐름을 검증했습니다. 통합 거점 문서저장소 이관 이후에도 현업이 기존 외래·응급 의뢰·회송 화면 안에서 수신 문서를 처리할 수 있도록 연결했습니다.
